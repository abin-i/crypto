### CCS 339 – Experiments 1 to 4: Windows setup and practical guide

We'll keep the same official Hyperledger Fabric repository, same sample chaincode, same asset names and same transaction operations wherever possible.

I'll separate the commands into two categories:

* Windows-native: PowerShell, Command Prompt and VS Code.

* Fabric scripts: Git Bash is worth testing, but it is not an officially guaranteed replacement for Linux. Hyperledger's current documentation recommends WSL2 for Windows because its test network depends on Bash and Linux-compatible utilities. GitHub +1

I don't want you to waste your practical time expecting an unsupported command to work. We'll first install and verify the Windows tools, then test the Fabric environment.

### Experiment 2 – Create and deploy a blockchain network

Aim: Create a Hyperledger Fabric network, create a channel, deploy chaincode and perform invoke/query operations.

### Step 1. Open Git Bash

Navigate to the test network:

```bash
cd ~/blockchain-lab/fabric-samples/test-network
```

If your folder is on the Windows C drive, the equivalent Git Bash path might look like:

```bash
cd /c/Users/YourWindowsUsername/blockchain-lab/fabric-samples/test-network
```

Replace `YourWindowsUsername` with your actual Windows account folder name.

### Step 2. Start the network

```bash
./network.sh up createChannel
```

This should start the Fabric network and create `mychannel`.

### Step 3. Deploy chaincode

```bash
./network.sh deployCC -ccn basic -ccp ../asset-transfer-basic/chaincode-go -ccl go
```

Here:

* `basic` = chaincode name.

* `-ccp` = chaincode folder path.

* `-ccl go` = chaincode programming language.

### Step 4. Set the peer environment

In Git Bash:

```bash
export PATH=${PWD}/../bin:$PATH
export FABRIC_CFG_PATH=${PWD}/../config/
export CORE_PEER_TLS_ENABLED=true
export CORE_PEER_LOCALMSPID=Org1MSP
export CORE_PEER_ADDRESS=localhost:7051
export CORE_PEER_MSPCONFIGPATH=${PWD}/organizations/peerOrganizations/org1.example.com/users/Admin@org1.example.com/msp
export CORE_PEER_TLS_ROOTCERT_FILE=${PWD}/organizations/peerOrganizations/org1.example.com/peers/peer0.org1.example.com/tls/ca.crt
```

These commands configure the peer identity, network address, certificates and Fabric binary location.

### Step 5. Query all assets

```bash
peer chaincode query -C mychannel -n basic -c '{"function":"GetAllAssets","Args":[]}'
```

This reads all assets from the ledger.

### Step 6. Create an asset

```bash
peer chaincode invoke -o localhost:7050 --ordererTLSHostnameOverride orderer.example.com --tls --cafile "${PWD}/organizations/ordererOrganizations/example.com/orderers/orderer.example.com/msp/tlscacerts/tlsca.example.com-cert.pem" -C mychannel -n basic -c '{"function":"CreateAsset","Args":["asset6","blue","20","Tom","500"]}'
```

### Step 7. Query the created asset

```bash
peer chaincode query -C mychannel -n basic -c '{"function":"ReadAsset","Args":["asset6"]}'
```

Expected ledger result

```json
{
  "ID": "asset6",
  "Color": "blue",
  "Size": 20,
  "Owner": "Tom",
  "AppraisedValue": 500
}
```

Result: The asset is created and retrieved from the blockchain ledger.

Important: Your manual calls this the Java SDK experiment, but the actual network deployment and asset commands above use Fabric CLI with Go chaincode. The Java SDK section in the manual only gives a short Java query example.

### Experiment 3 – Interact with a blockchain network using an application

Windows-native application setup

Aim: Create a Node.js application that interacts with Hyperledger Fabric.

You can do the application development in Windows without Ubuntu.

### Step 1. Open VS Code

* Open VS Code.

* Select File → Open Folder.

* Create and open a folder called `blockchain-app`.

* Select Terminal → New Terminal.

* Make sure the terminal is PowerShell.

Execute:

```powershell
npm init -y
```

### Step 2. Install the required packages

```powershell
npm install @hyperledger/fabric-gateway
npm install @grpc/grpc-js
```

These install the Fabric Gateway client and gRPC communication library.

### Step 3. Create the JavaScript file

In VS Code Explorer:

* Right-click the `blockchain-app` folder.

* Select New File.

* Name it `app.js`.

* Paste this code:

```javascript
const grpc = require("@grpc/grpc-js");

console.log("Blockchain Application Started");

console.log("Connecting to Hyperledger Fabric...");

async function main() {
    try {
        console.log("Connected to blockchain network");

        console.log("Submitting transaction...");

        console.log("Transaction completed");

        console.log("Querying blockchain ledger...");

    } catch (error) {
        console.error("Error:", error);
    }
}

main();
```

Save the file using `Ctrl + S`.

### Step 4. Execute the application

In the VS Code terminal:

```powershell
node app.js
```

Expected output:

```text
Blockchain Application Started
Connecting to Hyperledger Fabric...
Connected to blockchain network
Submitting transaction...
Transaction completed
Querying blockchain ledger...
```

Important: This is the demonstration code supplied by your manual. It prints these messages but does not actually connect to Fabric. For a real transaction and query, the Gateway connection, certificates, identity and transaction calls must be implemented, and the Fabric network must be running.

Result: A Node.js application is created and executed successfully.

### Experiment 4 – Develop and deploy an asset transfer application

Aim: Create, read and transfer ownership of digital assets using Hyperledger Fabric.

This experiment uses the same Fabric test network and chaincode as Experiment 2. You do not need to download everything again.

### Step 1. Open Git Bash

Navigate to:

```bash
cd /c/Users/YourWindowsUsername/blockchain-lab/fabric-samples/test-network
```

Use your actual Windows username and folder location.

### Step 2. Start the network

If the network is already running from Experiment 2, don't start another copy.

If it has been stopped, execute:

```bash
./network.sh up createChannel
```

### Step 3. Deploy chaincode

```bash
./network.sh deployCC -ccn basic -ccp ../asset-transfer-basic/chaincode-go -ccl go
```

If chaincode `basic` is already deployed on the running network, you do not need to deploy it again.

### Step 4. Configure the peer environment

If you opened a new Git Bash terminal, set these variables again:

```bash
export PATH=${PWD}/../bin:$PATH
export FABRIC_CFG_PATH=${PWD}/../config/
export CORE_PEER_TLS_ENABLED=true
export CORE_PEER_LOCALMSPID=Org1MSP
export CORE_PEER_ADDRESS=localhost:7051
export CORE_PEER_MSPCONFIGPATH=${PWD}/organizations/peerOrganizations/org1.example.com/users/Admin@org1.example.com/msp
export CORE_PEER_TLS_ROOTCERT_FILE=${PWD}/organizations/peerOrganizations/org1.example.com/peers/peer0.org1.example.com/tls/ca.crt
```

### Step 5. Create an asset

```bash
peer chaincode invoke -o localhost:7050 --ordererTLSHostnameOverride orderer.example.com --tls --cafile "${PWD}/organizations/ordererOrganizations/example.com/orderers/orderer.example.com/msp/tlscacerts/tlsca.example.com-cert.pem" -C mychannel -n basic -c '{"function":"CreateAsset","Args":["asset7","red","30","Alice","1000"]}'
```

This creates an asset with ID `asset7`.

### Step 6. Read asset details

```bash
peer chaincode query -C mychannel -n basic -c '{"function":"ReadAsset","Args":["asset7"]}'
```

Expected output:

```json
{
  "ID": "asset7",
  "Color": "red",
  "Size": 30,
  "Owner": "Alice",
  "AppraisedValue": 1000
}
```

### Step 7. Transfer ownership

```bash
peer chaincode invoke -o localhost:7050 --ordererTLSHostnameOverride orderer.example.com --tls --cafile "${PWD}/organizations/ordererOrganizations/example.com/orderers/orderer.example.com/msp/tlscacerts/tlsca.example.com-cert.pem" -C mychannel -n basic -c '{"function":"TransferAsset","Args":["asset7","Bob"]}'
```

This transfers ownership from Alice to Bob.

### Step 8. Verify the new owner

```bash
peer chaincode query -C mychannel -n basic -c '{"function":"ReadAsset","Args":["asset7"]}'
```

Expected output

```json
{
  "ID": "asset7",
  "Color": "red",
  "Size": 30,
  "Owner": "Bob",
  "AppraisedValue": 1000
}
```

Result: The asset is created, queried and transferred successfully using Hyperledger Fabric.
